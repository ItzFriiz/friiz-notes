# 材料处理与自查

## 分工

整章或多材料融合采用下表；局部修改由主 agent 直接处理。

| 工作 | 默认承担者 | 交付 |
|---|---|---|
| 录音清理压缩、课件文字与图片提取 | Luna（`gpt-6-luna`） | 材料摘要、出处、摘录、候选图和存疑项 |
| 结构、解释、符号、推导与最终修改 | 主 agent，使用 Friiz 当前选择的模型，当前约定为 6.1 sol | 正式笔记 |
| 首稿综合审查，重点查认知逻辑 | 独立子 agent，默认继承主模型 | 具体问题与最小修订建议 |

首稿默认只开一名综合审查者；纯格式或提取覆盖检查可交给 Luna，不另叠加重复审查。模型不可用或无委派工具时由主 agent 完成，说明实际分工。主 agent 对最终取舍负责。

## 材料处理与交接

主 agent 先读一个代表文件确认格式、任务范围及现有笔记，再委派边界清楚的提取任务；独立的录音和课件处理可并行。

- 只传必要上下文：文件与章节范围、所需主题、适用规范、输出位置和交接要求；给综合审查者提供实际认知记录及当前主题已确认的知识基础。优先不继承整段会话；子 agent 不递归拆分任务，不同时修改正式笔记。
- 录音压缩保留解释链、例子、教师限定、易错点和考核要求；课件保留定义、公式、条件及有用图像。无法核对的文字识别结果、转录词和来源冲突标为存疑，不补成确定事实。教师未提及某项内容不能据此压缩为“不考”。
- 按主题交接摘要、原文件及可定位位置、关键公式与限定、考核证据摘录、候选图及其用途、未解决项。区分原文、推断和未知；无时间戳时可用段落或检索短句定位。
- 大批结果写工作缓存文件，默认使用临时目录，汇报只给索引和关键存疑项。采用的图像和源码按 Obsidian 附件规则归档，内部定位不强制写进最终正文。

主 agent 按需读取摘要，回查关键公式、考核判断、冲突及采用的图像；不默认重读全部原文。压缩稿用于组织，原始材料仍是证据。正文按 `SKILL.md` 写作原则组织，不照抄提取顺序。

## 交付前自查

认知逻辑是首要项。写作与审查先读取 [理解与阅读偏好](learner-model.md) 和当前主题规范，只使用有记录依据或前文已建立的知识；不能用审查者自身的知识替作者补齐缺口。检查当前问题、已有前提，以及哪一步或哪一项回答了问题。

先判断理解障碍，再选择修改：

| 具体缺口 | 最小必要修改 |
| --- | --- |
| 术语或符号未定义 | 先交代对象类别、与主体的关系及作用，再引入代号；上下标不能代替对象差别的解释。定位整组笔记中最早出现处，避免后篇补定义而前篇仍留缺口 |
| 操作未交代 | 写明作用于哪个对象及具体规则；抽象集合或逆映射可用图标出给定量、满足条件的区域及最终取值，不用重复公式的框图代替解释 |
| 指标只有定义，没有判断方向 | 说明越大或越小越好及必要比较条件；一句能回答的问题不扩成推导、例子和用途清单 |
| 只有来源转述或结论标签，没有实质内容 | 将“以某差异说明某条件”“这是工程经验”等句子落实为具体差别、机制及后果；必要条件接在实质解释之后，无助于当前理解的内容直接删除 |
| 推理或因果跳跃 | 补缺失的前提、依据及连接步骤 |
| 比较没有凸显差别 | 统一符号并列公式，指出不同的变量依赖或交互项 |
| 已经回答问题，仍有重复说明 | 保留必要条件，删减重复动机、类比和复述；错误术语移除后，不再引入辨析它所需的额外概念 |

每条展开建议应指出具体缺口；原文已经足够时保持原文，不为完成审查而要求增加解释。

例如，解释 ELBO 与对数似然的差距时，从“对数似然减去 ELBO”展开，在差值中识别贝叶斯后验，再认出 KL 散度。修复顺序问题先移动或重组段落，不靠追加目的说明补救。

| 维度 | 检查重点 |
|---|---|
| 认知顺序（首要） | 读者为何需要这个概念、为何接着做这一步？是否先列辅助量或恒等式，后解释用途？是否依赖后文才定义的概念？ |
| 符号与对象 | 函数、变量、下标与算子是否定义？是否有冗余别名、符号切换、条件方向不清或函数与值混淆？ |
| 推导与正确性 | 关键步骤是否有依据和条件？论证的前提是否得到支持，而不只是编号列出？是否把“目前不知道”加强为“原则上不可能知道”，或未经桥接假设就从认识限制推出存在结论？是否突现恒等式、跳过必要计算，或混淆精确值、下界和近似梯度？ |
| 解释深度 | 展开建议依据哪条记录、当前反馈或正文中的具体缺口？公式能否直接凸显差别？是否遗漏必要连接，或用类比、动机和复述遮住关键项？ |
| 覆盖与依据 | 是否遗漏本次材料的关键内容或因不考而少讲？是否把旧卷、推断、未提及写成当前考纲？正文与图注是否夹带“课堂／课件中”等来源转述或整理旁白？理解所需的条件是否留在正文，出处与补充身份是否集中记在文末，考核证据是否另行汇总？ |
| 图文与格式 | 图是否有用且与正文一致？实际图片有无重叠、短箭头和小字？开头概览、标题编号、公式、粗体、callout、附件链接和来源是否符合 `obsidian.md`？ |

首稿交给独立审查者，提供当前笔记、规范、材料索引和图片，不预先给作者的辩解或预期结论。局部修改只复查受影响段落；长推导、结构或跨段符号变更可委派局部复查。图像审查须打开实际图片，不能只看源码。

审查者不改稿，只报告位置或短引文、具体问题及最小建议，区分正确性、理解障碍和可选精简。优先建议删减、合并、重排；建议加字时指出缺失的定义、前提或依据，不以“更详细”为理由。不确定项注明回查来源；未发现问题时说明实际审查范围。

主 agent 核实报告后修改，遵守当前文件与用户删改约定，再查受影响的符号、图和链接。同类格式错误按用户指定文件通查，不只改示例处；修复首次解释后，检查相邻篇章有无重复定义。核对粗体仅包中文、英文括注置于粗体外，并检查局部解释是否按用途使用卡片；术语已删改时，清理依赖旧表述的解释和改稿旁白。拿到独立课件后，复查仍在使用的录屏图或 DOCX 内嵌截图，优先换成课件原图并更新来源；存在转换困难不等于已完成替换。必要的二次审查只覆盖修改范围；材料稿和审查报告不附进学习笔记。
