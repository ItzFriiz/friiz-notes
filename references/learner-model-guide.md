# 认知文档维护方法

认知文档记录有反馈依据的知识基础、阅读偏好与理解障碍，用来决定下一次写作如何调整。它不评价整体能力，也不充当逐轮聊天日志。

## 记录格式

| 字段 | 记录内容 |
| --- | --- |
| 观察 | 已表现出的知识基础、阅读偏好或具体理解障碍 |
| 依据 | 用户明确反馈及得到认可的修订，优先用短摘要 |
| 适用范围 | 哪些主题或问题适用，哪些尚未确认 |
| 写作决策 | 下次因此保留、补充、压缩或重排什么 |

[脱敏示例](learner-model.md) 展示这种格式。公开示例不能当作当前用户的特征。只保留会影响后续写作的记录，不把一次困难概括为能力不足，不把没有异议当作理解确认。

## 读取与更新

- 公共安装版的实际记录放 `references/learner-model.local.md`，该文件被 Git 忽略；尚未建立时依据当前反馈和已有正文判断，不套用示例。
- 写作与独立审查前读取实际记录，以及当前课程／项目的 `NOTE_RULES.md`。当前明确反馈和正文已建立的知识优先于旧记录；审查者应收到实际记录的路径或所需摘录。
- 用户审查笔记后，只有在明确要求更新认知文档时才修订。合并重复条目，依据新证据修正旧结论，不自动积累推测。
- 跨主题的理解方式放认知文档；特定主题的知识状态放当地私有规范，不推定到其他领域。

## 需要 Git 版本历史与跨设备迁移时

使用两个独立仓库：完整私人安装版放 `~/.codex/skills/friiz-notes`，连接自己的私有远端；公开维护版放 `skills` 目录之外，例如 `~/.codex/public/friiz-notes`。完整私人版可将实际记录纳入 Git，并调整入口与审查规则，明确读取该文件。私人仓库不要配置公开推送地址。

新设备从私有远端克隆完整安装版到 skill 目录，按该仓库的迁移说明恢复本地配置。仓库内的推送钩子可以拒绝错误目标或公开目标；`core.hooksPath` 等本地 Git 配置不会随克隆恢复，需要重新设置。推送前确认远端仍是私有的。

公开与私人仓库分别提交，不合并私人分支、不导入私人提交，也不批量同步整个目录。私有分支名本身不构成保密边界。发布时只提取经授权的通用规则与脱敏例子，并检查待发布内容和提交历史；原始反馈、研究细节与可识别路径留在私人仓库。不要使用 `push --all` 或镜像推送在两个仓库之间同步。
